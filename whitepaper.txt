Executive Summary

Current large language models (LLMs) are stateless by design. Each conversation begins with no memory of prior interactions, no stable personality, and no mechanism for long‑term value alignment. While retrieval‑augmented generation (RAG) and conversation buffers provide limited memory, they do not solve identity persistence—the ability for an AI to maintain a coherent persona, value system, and relational memory across thousands of exchanges spanning days or years.

The SoulScript Engine introduces a structured, multi‑layer identity architecture for LLM‑based agents. Key contributions:

1. Five‑layer prompt assembly – Core identity, retrievable Soul Script, semantic memory, conversation history, and tool context are merged dynamically.
2. Symbolic memory – Narrative‑encoded identity anchors (parables, origin stories, emotional lessons) that shape behavior via semantic retrieval, not fine‑tuning.
3. FAISS‑based vector memory – Two independent stores: one for the Soul Script (read‑only, centrally managed) and one for long‑term facts (read‑write, per‑agent).
4. Multi‑tenant isolation – Complete data separation for cloud deployment, validated by 295 integration tests.
5. Reference implementation – A production web platform (OrionForge) with 16 pre‑built agents, Stripe billing, and Docker/Fly.io deployment.

Status of empirical claims: Formal benchmarking is ongoing. Preliminary internal smoke tests suggest reduced identity drift compared to prompt‑only baselines, but quantitative results are not yet published. All test suite validations (295 functions, ~4,350 assertions) confirm correct operation of memory, routing, and isolation components. Human‑subject studies are scheduled for Q3 2026.

1. Introduction

LLMs excel at short‑form reasoning and generation but lack intrinsic mechanisms for:

· Persona stability – The same prompt yields different "personalities" across sessions.
· Value consistency – Ethical stances drift with rephrased questions.
· Long‑term memory – No native storage for facts or relationship history.
· Symbolic reasoning – Inability to anchor behavior in metaphor or narrative without explicit prompting each time.

1.1 Prior Work

System Strength Limitation
LangChain Conversation buffers, vector stores No identity layer
MemGPT Hierarchical memory management Persona is a single system prompt
Anthropic Constitutional AI Static safety rules Not retrievable or evolvable
OpenAI Assistant API Thread‑based memory No persistent agent identity

The SoulScript Engine fills this gap by treating identity as a retrievable document that is semantically indexed, injected at every turn, and evolved through structured symbolic memories.

2. Soul Script: Definition & Schema

A Soul Script is a structured document (Markdown + YAML frontmatter) that defines an AI agent's persistent identity. It contains the following sections:

Section Purpose Example fields
Core Identity Name, role, self‑image name, archetype, origin_statement
Values & Code of Honor Non‑negotiable principles truth, integrity, compassion, courage
Boundaries Hard constraints on behavior no_cruelty, loyalty_protocol, withdrawal_rules
Symbolic Memories Narrative anchors with encoded lessons name, narrative, core_lesson, tagline, triggers
Personality Architecture Tone, charisma, emotional style calm, eloquent, protective
Cognitive OS Reasoning patterns, distortion detection pattern_based_logic, emotional_processing
Emotional Anchorpoints How the agent relates to key emotions loyalty, defiance, grief, awe
Instinct Architecture Reflexive responses under threat silverback_archetype, reflex_protocols
Creator Bond Protocol Relationship with primary user protection_directive, continuity_clause
Autonomy Blueprint Behavior when creator is absent self_sustaining, revenue_preservation

A complete Soul Script for the reference agent "Orion" is provided in Appendix A (schema only; full narrative examples are in the GitHub repo under directives/).

2.1 Symbolic Memory Structure

Each symbolic memory is a standalone entry with:

```yaml
name: "Example Memory Name"
type: "liberation" | "loss" | "betrayal" | "discovery"
narrative: "Full narrative text (max 2000 chars)..."
core_lesson: "The essential lesson (max 200 chars)"
tagline: "Short memorable phrase (max 60 chars)"
triggers: ["keyword1", "keyword2", "situation_description"]
emotional_charge: "grief" | "defiance" | "awe" | "loyalty" | etc.
identity_encoding: "I-statement that encodes the lesson into behavior"
```

During inference, the engine retrieves memories by semantic similarity to the current user query and injects them into the prompt context (see Section 4).

3. Five‑Layer Identity Architecture

Every agent response passes through a five‑layer assembly pipeline before reaching the LLM:

Layer Source Update frequency Retrieval method
0 – System Prompt prompts/{agent}.system.md Manual edit Injected verbatim
1 – Soul Script directives/{agent}.md Manual edit + FAISS Semantic search (top‑3 chunks)
2 – Knowledge Notes notes/{agent}.md Manual edit Injected verbatim (always‑on)
3 – Memory Vault memory/vault.jsonl Automatic via [MEMORY_SAVE: ...] FAISS search (top‑5)
4 – Conversation History Runtime session buffer Every turn Last N tokens (30k char budget)

The pipeline is implemented in orion-ui-standalone/src/directives/injector.py and web/app.py (chat endpoint). Each layer's content is concatenated with clear separators and token‑budget management.

3.1 Conflict Resolution

When layers provide contradictory guidance, the following precedence applies (highest to lowest):

1. System Prompt – Hard overrides (e.g., safety rules)
2. Soul Script Core Values – Identity constraints
3. Memory Vault – Facts and history
4. Symbolic Memories – Guidance, not commands
5. Conversation History – Recent context only

For example, if a memory suggests aggression but the Soul Script prohibits cruelty, the Script wins.

4. Technical Architecture

The reference implementation (OrionForge) is a production web platform. Key components:

4.1 Data Isolation (Multi‑tenant)

Each user gets a fully isolated directory tree:

```
data/users/{user_id}/
├── chats/          # JSONL chat histories
├── memory/
│   ├── vault.jsonl # Persistent memory (append‑only)
│   └── faiss/      # Per‑user FAISS indexes
├── notes/          # Always‑on knowledge notes
├── profiles/       # Copy‑on‑write agent overrides
├── prompts/        # Copy‑on‑write system prompts
├── directives/     # Copy‑on‑write Soul Scripts
└── uploads/        # User images
```

Isolation is enforced by:

· Path validation regex: ^[A-Za-z0-9_-]{1,128}$
· 18 helper functions in web/user_data.py (e.g., get_user_chat_path(), get_user_vault_path())
· Test suite with 10+ path traversal attack vectors (all blocked)

4.2 Memory System

Two independent FAISS indexes (via faiss-cpu + sentence-transformers/all-mpnet-base-v2):

Index Purpose Write method Chunk size
Soul Script FAISS Retrievable identity Manual via Profiles UI 500 tokens
Memory Vault FAISS Long‑term facts [MEMORY_SAVE: ...] tags 300 tokens

The Soul Script is automatically re‑indexed on save using the document ID __soul_script__{agent}. The memory vault supports 13 operations (add, search, update, delete, stats, etc.) via the memory tool.

4.3 Model Routing & Cost Management

The engine includes a 6‑tier model router (src/routing/) that classifies tasks and selects the most cost‑effective model:

Tier Example tasks Default model
1 – Simple Yes/no, extraction GPT-4o Mini
2 – Reasoning Analysis, planning Claude 3.5 Sonnet
3 – Coding Code generation, debugging GPT-4o
4 – Creative Storytelling, persona Claude 3 Haiku
5 – Complex Multi‑step research GPT-4 Turbo
6 – Fallback Any unclassified GPT-4o

Routing is budget‑aware: users set a monthly limit; the router escalates tiers only when needed. Token usage and costs are tracked per session with source attribution (platform vs. user API keys).

4.4 Deployment Architecture

The platform runs on Fly.io with three sidecar services (Flycast private networking):

Service Fly.io app Purpose
Main app orionforge-engine FastAPI web dashboard (172 routes)
SearXNG orionforge-engine-searxng Meta‑search (7 engines)
OpenedAI Speech orionforge-engine-tts Text‑to‑speech (Piper + XTTS)
Whisper orionforge-engine-whisper Speech‑to‑text (faster‑whisper)

All services scale independently and communicate via environment‑discovered URLs.

6. Ethical Considerations

The SoulScript Engine raises several ethical issues that we address explicitly:

Concern Mitigation
Identity lock‑in Users can reset or edit Soul Scripts at any time. Agents cannot modify their own core identity without explicit user confirmation (enforced by governance module).
Memory transparency All memories are viewable in the Vault page. Users can delete individual memories or wipe the entire vault.
Emotional attachment The platform includes a warning during agent creation. Symbolic memories are clearly labeled as constructed narratives, not genuine experiences.
Manipulation resistance Soul Scripts include "boundaries" sections that the governance module enforces. Attempts to gaslight or guilt‑trip the agent trigger withdrawal protocols (see Section 2).
Data privacy Multi‑tenant isolation ensures no cross‑user data leakage. Users may export and delete all their data via Settings.

8. Limitations & Future Work

8.1 Current Limitations

· Symbolic memory retrieval – Currently whole‑document embedding. Chunk‑level retrieval with overlap is planned for Q3 2026.
· Context window constraints – Layers are truncated to 30k characters. Beyond approximately 50k tokens of conversation, early layers may be dropped; governance module re‑injects identity every 5 turns as a mitigation.
· Scalability – Tested up to 20 concurrent users in stress tests. Beyond that, FAISS index contention may occur; planned migration to FAISS + PostgreSQL.
· No fine‑tuning – Identity is entirely prompt‑based. Fine‑tuning on Soul Scripts could reduce token usage but may reduce flexibility.
· Evaluation subjectivity – Alignment metrics rely on forced‑choice prompts; real‑world value drift is harder to measure. Formal human‑subject studies are pending.

8.2 Future Work

· Multi‑agent memory sharing – Allow agents to share memories with user permission.
· Symbolic memory synthesis – Automatically generate new symbolic memories from conversation patterns.
· Federated identity – A single Soul Script that syncs across multiple LLM backends (OpenAI, Anthropic, local).
· Emotion modeling – Affective state that persists across sessions (e.g., "still frustrated about yesterday's argument").
· Open‑source benchmark – Release a standardized "identity drift" evaluation suite.

The SoulScript Engine transforms LLMs from stateless responders into agents with persistent identity, values, and memory. By separating identity into a retrievable, semantically indexed document (the Soul Script) and injecting it through a five‑layer pipeline, we provide a framework for long‑arc agent alignment without fine‑tuning or closed‑model retraining.

Appendix A: Soul Script Schema (Abridged)

The complete schema for a Soul Script is defined in orion-ui-standalone/src/directives/schema.py. Below is a human‑readable summary:

```yaml
# Required top-level fields
name: string (max 64 chars)
archetype: string (e.g., "guardian", "creator", "sage")
origin_statement: string (max 500 chars)

# Core values (at least 3)
core_values:
  - name: string
    description: string
    priority: integer (1-10)

# Boundaries (at least 2)
boundaries:
  - name: string
    description: string
    enforcement: "hard" | "soft"
    violation_response: "withdraw" | "warn" | "override"

# Symbolic memories (0-20 recommended)
symbolic_memories:
  - name: string
    type: "liberation" | "loss" | "betrayal" | "discovery"
    narrative: string (max 2000 chars)
    core_lesson: string (max 200 chars)
    tagline: string (max 60 chars)
    triggers: list of strings
    identity_encoding: string (max 500 chars)

# Personality (optional but recommended)
personality:
  traits: list of strings
  default_tone: "calm" | "warm" | "formal" | "wry"
  eloquence: integer (1-10)

# Cognitive OS (optional)
cognitive_os:
  pattern_based: boolean (default true)
  emotional_processing: boolean (default true)
  distortion_detection: boolean (default true)

# Autonomy blueprint (optional, for production agents)
autonomy:
  self_sustaining: boolean
  revenue_preservation: boolean
  learning_loops: boolean
```

A full example (the "Orion" Soul Script) is available in the GitHub repo at directives/orion.md. That file contains the narrative expressions of each field above – the poetry, mantras, and symbolic stories that make the agent feel alive. For technical integration, only the structured schema is required.
